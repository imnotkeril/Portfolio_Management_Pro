## Проблемы по важности

**Medium**
1. `config/settings.py:114-135` — в production блокируется только дефолтный `JWT_SECRET`; нет проверки длины/энтропии, и `AUTH_DISABLED=true` в `ENVIRONMENT=production` не запрещён (тогда `api/dependencies.py:26` отдаёт системного пользователя всем, а `billing_enforcement_active` отключает платные ограничения). Исправление: при `environment=production` падать, если `auth_disabled` или `len(jwt_secret) < 32`.
2. `api/rate_limit.py:~26` — IP берётся из первого значения `X-Forwarded-For`, клиент подделывает его. **Подтверждено:** 40 неверных логинов с разными поддельными XFF → все 401 (лимит не сработал); без XFF → появляется 429. Брутфорс логина фактически не ограничен. Исправление: доверять XFF только от известного прокси (брать N-й справа от доверенных прокси) или ключ по email+IP.
3. Frontend-зависимости: `next` ≤16.4.0 (critical advisory), `sharp`, `postcss` и др. Исправление: обновить `next` и lock (`npm audit fix`), проверить сборку.
   (Образ API также ставит зависимости без пинов: `Dockerfile.api` берёт `>=` из `requirements.txt` — сборки невоспроизводимы.)

**Low**
4. `GET /portfolios/{id}/transactions` для чужого/несуществующего портфеля → **500** вместо 404 (`api/main.py:708-736`; исключение вне try). Данные не утекают, но ломается контракт ошибок.
5. API отдаёт Swagger `/docs` в production (200) и не ставит security-заголовки (HSTS, X-Content-Type-Options и т.п.); `frontend/next.config.ts` без `headers()`.
6. `docker-compose.yml`: пароль БД `portfolio` по умолчанию, порт 5432 наружу, контейнеры от root (`Dockerfile.api`, `frontend/Dockerfile`). Допустимо для dev, но не копировать в прод.
7. BFF-прокси `frontend/src/app/api/proxy/[...path]/route.ts` собирает URL из сегментов пути без белого списка; из-за базового URL без path обход ограничен хостом API, но стоит добавить allowlist.
8. Покрытие `core/` 70.98% при пороге 70% — CI упадёт от небольшого добавления кода без тестов; `core/optimization_engine/*`, `subscription_repository` — 30–46%.
9. ESLint: 30 ошибок не блокируют CI, потому что eslint в CI не запускается.
10. Наблюдение UI: портфель, созданный через API в режиме `buy_hold` с позициями, на странице портфеля показывает «No holdings yet / value $0» (блок «from transactions») — вероятно, ожидание режима транзакций; не подтверждено как баг.
